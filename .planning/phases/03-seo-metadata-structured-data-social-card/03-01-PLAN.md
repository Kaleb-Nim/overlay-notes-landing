## Phase Goal

**As a** search crawler or social scraper hitting the finished page, **I want to** receive
correct, absolute, new-domain metadata plus a `SoftwareApplication` JSON-LD block and
crawl-surface routes, **so that** the page is discoverable in search and never leaks a
stale reference back to the old GitHub Pages domain.

_(Derived faithfully from ROADMAP.md Phase 3 Goal — no scope invented.)_

<objective>
Extend the served page's build-time SEO output so every crawler-facing surface is correct
and absolute: the `<head>` metadata (title/description/canonical/OG/Twitter), the
`SoftwareApplication` JSON-LD block, the `robots.txt`/`sitemap.xml` file-convention routes,
and the env-gated preview-deployment `X-Robots-Tag: noindex` header.

This is the first vertical slice of Phase 3 — a complete, independently-verifiable
"crawler reads the page" capability. It ships without the OG image file (produced by plan
03-02); the `og:image` meta tag already resolves correctly via `metadataBase` regardless.

Purpose: Satisfy SEO-01..09 — the correctness half of the phase goal.
Output: Extended `app/layout.tsx`, new `app/robots.ts` + `app/sitemap.ts`, extended
`next.config.ts`.
</objective>

## Phase Goal

ROADMAP.md states this phase's goal in outcome form, not user-story form (verbatim): *"The
content-complete, SEO-correct page is live on a public GitHub repo, deployed to Vercel, and
reachable at `overlay-notes.kalebnim.dev` with analytics reporting — with the custom domain
attached only after content and SEO are confirmed correct, so the production domain is never
indexed half-built."* No user story is invented here — see the planner's return note.

**User-observable increment delivered by this plan:** a visitor handed a URL can load the
finished landing page on the public internet for the first time, and the author can point
anyone at a public GitHub repo for the source. Nothing about the page changes — its
reachability does.

<objective>
Publish the existing repo publicly to GitHub and stand up the Vercel project that builds and
deploys it automatically, then prove the deployed output is correct on its Vercel-generated
URL — before any custom domain exists (DEPL-01, DEPL-02; ROADMAP Success Criteria #1 and #2).

Purpose: this is the irreversible half of the phase. Once the repo is public it cannot be
meaningfully un-published, so the pre-publish audit runs first and the domain attach is held
back to 04-02 entirely.
Output: a public GitHub repo, a git-connected Vercel project, a verified production deployment
on `*.vercel.app`, a proven PR preview deployment, plus `README.md`,
`scripts/verify-deployment.sh`, and a `verify:deploy` package script.
</objective>

  attaching the custom domain "removes Vercel's default noindex protection." 04-RESEARCH.md

  a project's production-targeted `*.vercel.app` alias. The **sequencing is kept anyway** as a hard

  its own merits and costs nothing. The corrected mechanism is recorded here as an assumption; the

  header or middleware logic to "fix" this** — that is unrequested scope outside DEPL-01..04.

<resumability>
## What is guaranteed if this plan is interrupted or re-run (DEPL-02 concurrency probe)

**Guaranteed:** every step's effect is independently observable, so a resumed run re-derives
state instead of assuming it. Partial state is forward-recoverable; nothing needs rollback.

| Step | Idempotent? | Probe before running | Behaviour on re-run |
|------|-------------|----------------------|---------------------|
| `gh repo create` | No — errors if the name exists | `gh repo view Kaleb-Nim/overlay-notes-landing --json name` | Skip creation; ensure `origin` + `git push -u origin main` instead |
| `git remote add origin` | No — errors if `origin` exists | `git remote -v` | Skip; verify the URL matches |
| `vercel project add` | No — errors if the project exists | `vercel project ls` | Skip creation |
| `vercel link --yes --project` | Yes | — | Safe; rewrites `.vercel/project.json` |
| `vercel git connect --yes` | Yes | `vercel project inspect` | "Already connected" is success, not failure |
| `vercel --prod` | Yes (creates a new deployment each time) | — | Safe; a duplicate deployment is harmless |
| Disposable PR (Task 3) | No | `gh pr list --head <branch>` | Reuse the open PR rather than opening a second one |

**Not guaranteed / not supported:** parallel execution. This plan mutates shared external
resources (one GitHub repo, one Vercel project) that admit no concurrent writer. It is the sole
plan in wave 1 precisely so no sibling plan can race it. Do not run two executors against this
plan.
</resumability>
